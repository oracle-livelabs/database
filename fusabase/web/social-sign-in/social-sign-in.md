# Add Google Social Sign-In

## Introduction

In this optional lab, you will configure Google as a social-login provider for the Fusabase project you created in the Recipe Share workshop. You will then add a **Sign in with Google** button to the app and authenticate with the Fusabase JavaScript SDK.

Google creates the OAuth client credentials, while Fusabase manages the sign-in flow and creates the Fusabase user on the first successful Google sign-in.

### Objectives

In this lab, you will:

- retrieve the Google redirect URI generated by Fusabase
- create a Google OAuth 2.0 client for a web application
- enable Google social login in the Fusabase console
- add `GoogleAuthProvider` and `signInWithPopup` to Recipe Share
- sign in to Recipe Share with a Google account

Estimated Time: 20 minutes

### Prerequisites

This lab assumes you have:

- Completed Labs 1 through 7 of this workshop.
- A Google account that can create or use a Google Cloud project.
- Kept Recipe Share running locally from the previous labs.

> Note: This lab changes the configuration of your Fusabase project and your Google Cloud project. Do not use production credentials or a production project while learning. The client secret belongs only in the Fusabase console; never add it to browser code or commit it to source control.

## Task 1: Get the Fusabase redirect URI

1. Open the Fusabase console for the Recipe Share project.

2. Open **Authentication**, then open **Social login**.

3. Locate **Google** and select its action or configuration control.

    ![Fusabase Authentication Social login list with Google available as a provider](images/fusabase-social-login.png =85%x*)

4. Copy the **Redirect URI**. Copy that URI exactly, including its path. You will add it to the Google OAuth client in the next task.

    ![Google provider configuration showing the generated Fusabase redirect URI](images/fusabase-google-redirect-uri.png =85%x*)

5. Do not save the provider yet; you still need the Google client ID and client secret. Close or cancel the panel when you have copied the redirect URI.

## Task 2: Create a Google OAuth client

1. Open the [Google Cloud console](https://console.cloud.google.com/) and select or create a project for this lab.

2. Configure the OAuth consent screen / Google Auth Platform branding for the project if Google prompts you to do so. Use a test audience while you are developing.

3. Open **APIs & Services**, then **Credentials**. Create an **OAuth client ID**.

    ![Google provider configuration showing the generated Fusabase redirect URI](images/console.png =65%x*)

    ![Google provider configuration showing the generated Fusabase redirect URI](images/id.png =65%x*)

4. Choose **Web application** as the application type. Give it a clear name, such as `RecipeShare Fusabase`.

5. Under **Authorized redirect URIs**, paste the Redirect URI you copied from the Fusabase console. Do not use your local Recipe Share URL here; use the Fusabase-generated URI.

6. Create the OAuth client. Copy its **Client ID** and **Client secret**. You can download the client JSON for safekeeping, but do not add it to the Recipe Share project.

## Task 3: Enable Google in Fusabase

1. Return to the Fusabase console and open **Authentication** > **Social login** > **Google**.

2. Paste the Google OAuth **Client ID** and **Client secret** from the previous task.

3. Ensure the provider is enabled, then select **Save**.

    ![Configured Google provider in the Fusabase Social login page](images/fusabase-google-provider-configured.png =85%x*)

Google is now available to Fusabase as an identity provider. The remaining tasks add the UI and SDK call that starts the popup flow in Recipe Share.

## Task 4: Add the Google button

1. In your Recipe Share project, open `starter/index.html`.

2. In the auth popup, find the two buttons below the email and password fields:

    ```html
    <button id="signInButton" class="btn btn-primary" type="button">Sign in</button>
    <button id="signUpButton" class="btn btn-outline" type="button">Create account</button>
    ```

3. Add the Google button between them (around line 37):

    ```html
    <copy>
    <button id="signInWithGoogleButton" class="btn btn-outline" type="button">Sign in with Google</button></copy>
    ```

4. Save the file and sign out of the app if you are still signed in.

    ![Recipe Share sign-in popup with the Sign in with Google button](images/recipe-share-google-button.png =85%x*)

    ![HTML showing the new Sign in with Google button in the auth popup](images/add-google-button-code.png =85%x*)

## Task 5: Sign in through Google with the SDK

1. Open `starter/scripts/app.js`.

2. Update the import from `fusabase/auth` to include `GoogleAuthProvider` and `signInWithPopup`:

    ```js
    <copy>import {
      GoogleAuthProvider,
      createUserWithEmailAndPassword,
      getAuth,
      onAuthStateChanged,
      signInWithPopup,
      signInWithEmailAndPassword,
      signOut
    } from "fusabase/auth";</copy>
    ```
    ![JavaScript element map showing signInWithGoogleButton](images/google.png =65%x*)

3. In the `el` object, add the new button after `signInButton`:

    ```js
    <copy>signInWithGoogleButton: document.querySelector("#signInWithGoogleButton"),</copy>
    ```

    ![JavaScript element map showing signInWithGoogleButton](images/add.png =85%x*)

4. In `bindEvents()`, add this listener after the existing `signInButton` listener:

    ```js
    <copy>el.signInWithGoogleButton.addEventListener("click", () => {
      runAction("Signed in with Google.", async () => {
        await signInWithPopup(auth, new GoogleAuthProvider());
      });
    });</copy>
    ```

    `GoogleAuthProvider` identifies Google as the configured provider. `signInWithPopup()` opens the OAuth flow and resolves after Fusabase has authenticated the user.

    ![Google popup sign-in click listener in app.js](images/google-listener-code.png =85%x*)

5. Save the file.

## Task 6: Verify Google sign-in

1. Refresh Recipe Share at [http://localhost:8000/starter/](http://localhost:8000/starter/).

2. Select **Sign in**, then select **Sign in with Google**.

3. Complete the Google account selection and consent flow in the popup.

4. When the popup closes, Recipe Share should show the Google account email and the **Sign out** button. The recipe and rating forms should be enabled, just as they are for email/password users.

    ![Recipe Share signed in with a Google account](images/recipe-share-google-signed-in.png =85%x*)

5. In the Fusabase console, open **Authentication** and confirm that a user was created for the Google account.

6. If `starter/scripts/app.js` or `starter/index.html` does not work after this lab, use `checkpoints/app-after-lab-8.js` and `checkpoints/index-after-lab-8.html` to replace the corresponding files. Keep your own `starter/fusabase-config.js`.

### Troubleshooting

- If Google reports a redirect-URI mismatch, compare the authorized redirect URI in Google Cloud character-for-character with the URI shown in Fusabase.
- If the Fusabase console reports that the provider is not configured, confirm that Google is enabled and that both client credentials were saved.
- If the popup closes without signing in, allow popups for `localhost` and retry.
- If the same email already has an account created through a different provider, the sign-in can fail because the accounts are not automatically linked. Use a new test account or remove the conflicting test user before retrying.

    ![Fusabase authentication user list showing a conflicting social-login account](images/social-login-conflicting-account.png =85%x*)

You have now added Google social sign-in to Recipe Share. You may now **proceed to the next lab**.
