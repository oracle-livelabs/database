# Search Images with Private AI Services Container

## Introduction

Text embeddings let you search for similar meaning. Multimodal embeddings extend the same idea across text and images. A text phrase such as `waterfall` and a photograph of a waterfall can be represented in the same vector space, making text-to-image and image-to-image search possible with the same vector-distance operators used in the previous labs.

This lab uses the CLIP text and image embedding services in the Private AI Services Container. The source images are stored as BLOBs in Autonomous AI Database Serverless. Keeping the image bytes in the database makes the exercise repeatable and avoids depending on public image servers while the lab is running.

Estimated Time: 20 minutes

### About the Image Data

The workshop environment includes a curated collection of approximately 2,000 National Parks images in `PARK_IMAGES_BLOB`. Each row contains the image, descriptive metadata, source attribution, and a 512-dimensional vector generated by the container's `clip-vit-base-patch32-img` model.

The container exposes two compatible CLIP services:

* `clip-vit-base-patch32-txt` converts text into a 512-dimensional vector.
* `clip-vit-base-patch32-img` converts image bytes into a 512-dimensional vector.

Because the two models produce vectors in the same embedding space, a text vector can be compared with image vectors.

### Objectives

In this lab, you will:

* Inspect the image BLOB and vector data
* Generate a text embedding through the Private AI Services Container
* Search image vectors with a text phrase
* Generate an embedding from a stored image BLOB
* Search for images similar to another image
* Combine vector similarity with relational filters

### Prerequisites

This lab assumes you have:

* Completed the previous labs
* A healthy Private AI Services Container endpoint in `PRIVATE_AI_CONFIG`
* A populated `PARK_IMAGES_BLOB` table with image BLOBs and 512-dimensional vectors

## Task 2: Search Images with Text

Generate the remote embedding in an uncorrelated scalar subquery. Oracle evaluates the scalar subquery once and uses that vector while scanning the stored image vectors.

1. Search the stored image vectors with a CLIP text vector for `Civil War`.

    ```sql
    <copy>
    SELECT i.image_id,
           i.title,
           i.description,
           i.park_code,
           i.source_url,
           VECTOR_DISTANCE(
             i.image_vector,
             (
               SELECT DBMS_VECTOR.UTL_TO_EMBEDDING(
                        'Civil War',
                        JSON_OBJECT(
                          'provider' VALUE 'privateai',
                          'credential_name' VALUE NULL,
                          'url' VALUE config_value || '/v1/embeddings',
                          'host' VALUE 'local',
                          'model' VALUE 'clip-vit-base-patch32-txt'
                          RETURNING JSON
                        )
                      )
               FROM private_ai_config
               WHERE config_name = 'HTTP_ENDPOINT'
             ),
             COSINE
           ) AS distance
    FROM park_images_blob i
    ORDER BY distance
    FETCH EXACT FIRST 10 ROWS ONLY;
    </copy>
    ```

    The container generated the query vector, while Autonomous AI Database Serverless compared that vector with the stored image vectors.

    ![Image search results using a CLIP text embedding](images/clip-text-image-search.png " ")

## Task 3: Search with a Stored Image

The BLOB overload of `DBMS_VECTOR.UTL_TO_EMBEDDING` accepts the image bytes directly. The modality argument tells the package to submit the input as an image.

1. Choose one image tagged for rock climbing and search for the ten closest images.

    ```sql
    <copy>
    SELECT i.image_id,
           i.title,
           i.description,
           i.park_code,
           i.source_url,
           VECTOR_DISTANCE(
             i.image_vector,
             (
               SELECT DBMS_VECTOR.UTL_TO_EMBEDDING(
                        source_image.image_blob,
                        'image',
                        JSON_OBJECT(
                          'provider' VALUE 'privateai',
                          'credential_name' VALUE NULL,
                          'url' VALUE c.config_value || '/v1/embeddings',
                          'host' VALUE 'local',
                          'model' VALUE 'clip-vit-base-patch32-img'
                          RETURNING JSON
                        )
                      )
               FROM (
                 SELECT image_blob
                 FROM park_images_blob
                 WHERE UPPER(source_query) = 'ROCK CLIMBING'
                   AND image_blob IS NOT NULL
                 ORDER BY image_id
                 FETCH FIRST 1 ROW ONLY
               ) source_image
               CROSS JOIN private_ai_config c
               WHERE c.config_name = 'HTTP_ENDPOINT'
             ),
             COSINE
           ) AS distance
    FROM park_images_blob i
    ORDER BY distance
    FETCH EXACT FIRST 10 ROWS ONLY;
    </copy>
    ```

    The scalar subquery sends only the selected BLOB to the container once. The outer query compares the returned vector with the image vectors already stored in the database.

    ![Similar images found from a stored rock-climbing image](images/clip-stored-image-search.png " ")

## Task 4: Combine Vector and Relational Search

Vector search can be combined with ordinary SQL predicates and joins. Generate a CLIP text vector for `waterfall` inside the query, then limit the results to parks in the western United States.

1. Combine image similarity with park location data.

    ```sql
    <copy>
    SELECT i.image_id,
           i.title,
           p.name AS park_name,
           p.city,
           p.states,
           i.source_url,
           VECTOR_DISTANCE(
             i.image_vector,
             (
               SELECT DBMS_VECTOR.UTL_TO_EMBEDDING(
                        'waterfall',
                        JSON_OBJECT(
                          'provider' VALUE 'privateai',
                          'credential_name' VALUE NULL,
                          'url' VALUE config_value || '/v1/embeddings',
                          'host' VALUE 'local',
                          'model' VALUE 'clip-vit-base-patch32-txt'
                          RETURNING JSON
                        )
                      )
               FROM private_ai_config
               WHERE config_name = 'HTTP_ENDPOINT'
             ),
             COSINE
           ) AS distance
    FROM park_images_blob i
    JOIN parks p
      ON p.park_code = i.park_code
    WHERE p.states IN ('CA', 'OR', 'NV', 'WA', 'AZ', 'CO')
    ORDER BY distance
    FETCH EXACT FIRST 10 ROWS ONLY;
    </copy>
    ```

    The result demonstrates the open division of work used throughout the workshop: the container generates embeddings, while Autonomous AI Database Serverless stores the data and combines vector similarity with relational SQL.

    ![Waterfall image search combined with relational location filters](images/clip-relational-waterfall-search.png " ")
