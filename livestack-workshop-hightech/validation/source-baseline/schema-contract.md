# Manufacturing data model and loader contract

### Objectives

- Document the manufacturing schema, loader fixtures, relationships, and lab-created objects.

Estimated Time: **10 minutes**

The canonical SQL creates 15 tables, four reporting views, one JSON Relational Duality view, and the SQL property graph `PRODUCTION_QUALITY_NETWORK`. There are 18 foreign keys. `COMPONENT_EMBEDDINGS` receives 192 vectors at runtime; the manual database walkthrough verified these using the Oracle embedding model.

## Operational rules

- A plant produces components using a material grade and process route. Production orders belong to a plant and a customer site; each order line uses a component from that plant.
- Quantity is a unit count, independent of scheduled duration. Order total equals the sum of generated line totals plus setup cost.
- Inspection records hold inspected/rejected units, defect percentage, rework minutes, downtime, and corrective actions. Eight observations per component yield 1,536 inspection rows.
- Customer JSON describes material certificates, inspection reports, and delivery windows. Orders expose relational data as JSON without a second order store.
- Graph entities are orders, material lots, machines, suppliers, inspections, certificates, and plants. The three sample orders share lot LOT-ST-91A7. Graph risk scores are synthetic values for practicing review; they do not establish a defect.
- Spatial points and demand-region polygons use SRID 8307. Nearest distance alone does not verify machine capability, certification, inventory, schedule, or transport feasibility.
- OML uses component inspection and production aggregates from September 2026. REVIEW requires a mean defect rate of at least 3% and at least two stoppages of 60 minutes or longer. The fixture has 96 REVIEW and 96 STABLE examples. The same-window synthetic label is useful for teaching scoring, but does not show how well the model predicts future defects. A production study needs later outcomes and separate test data, with no target information included in the model inputs.
- Select AI uses COMPONENTS, PRODUCTION_ORDERS, PRODUCTION_ORDER_LINES, and CUSTOMER_SITES. Material-value prompts exclude setup cost and select released, in-production, or completed orders. An agent prompt is not an access-control boundary.

## Lab-created objects

`THOMAS_APP_DATA` demonstrates JSON columns; `THOMAS_PRODUCTION_ORDER_DOCS` demonstrates a collection table. Lab 2 enables INSERT and UPDATE on the root and child of `PRODUCTION_ORDERS_DV`; the loader starts with UPDATE only. Order 900001 and line 990001 are reserved for this exercise. Component 1 costs 125 USD, so two units have a material value of 250 USD.

Lab 3 adds `COMPONENTS.COMPONENT_EMBEDDING`; the dashboard uses the separately preloaded `COMPONENT_EMBEDDINGS` table. Lab 6 creates `OTTO_QUALITY_REVIEW_SETTINGS`, `OTTO_QUALITY_REVIEW_SCORING_DATA`, and model `OTTO_QUALITY_REVIEW_MODEL`. Lab 8 creates the `NINA_MANUFACTURING_*` AI tool, agent, task, and team.

The supplemental 43-paragraph notebook uses work centers and physical material transfers. Its `MATERIAL_FLOW_GRAPH` PGQL setup is provided at the end of the loader and must be run separately in Graph Studio. Rework paths explain cycles. It teaches paths, degree, PageRank, shortest path, personalized PageRank, and hop distance. The main eight-paragraph notebook uses SQL/PGQ.
