# Conclusión

## Introducción

Ha recorrido el flujo financiero principal de Seer Bank: entender los datos, explicar los riesgos del panel, revisar la información de las transacciones, buscar el lenguaje de riesgo por significado, seguir las relaciones de delitos financieros, evaluar la cobertura de servicios y puntuar modelos predictivos.

La idea principal es práctica: ahora puede explicar cómo una pregunta financiera puede utilizar varios tipos de datos sin perder el contexto necesario para revisar el resultado.

Una persona de negocio puede comenzar con un KPI del panel. Un desarrollador puede necesitar la transacción como JSON. Un investigador de fraude puede necesitar rutas de relaciones. Una persona de operaciones de servicio puede necesitar distancias y capacidad de atención de casos. Un planificador puede necesitar una predicción. Son trabajos diferentes, pero no deberían requerir copias de datos separadas ni explicaciones independientes.

Con **Oracle AI Database 26ai**, **Seer Bank** puede utilizar la capacidad adecuada para cada pregunta y mantener conectada la información: SQL relacional para las operaciones, JSON Relational Duality para los documentos de la aplicación, AI Vector Search para el significado, Property Graph para las relaciones, Oracle Spatial para la ubicación y Oracle Machine Learning (OML) para las predicciones.

> Este es el mensaje principal para las finanzas: *la base de datos no es solo el lugar donde se guardan los registros. Se convierte en el lugar donde los equipos de riesgos, fraudes, cumplimiento, servicios y análisis pueden hacer preguntas diferentes sobre los mismos datos controlados.*

Al terminar este taller tendrá una forma práctica de explicar el valor de una base de datos convergente de Oracle: menos copias de datos sensibles, menos puntos de reconciliación, un control más sólido, investigaciones más rápidas y resultados que pueden explicarse a partir de información respaldada por SQL.

<details>
<summary><strong>Por qué importa: después del taller</strong></summary>

> Las decisiones financieras reales rara vez encajan en una sola categoría tecnológica. Una revisión de riesgo de un producto puede necesitar filas de transacciones, texto normativo, exposición de clientes, relaciones de fraude, ubicaciones de centros de servicio y puntuaciones predictivas.
>
> En un entorno fragmentado, cada pregunta puede enviar al equipo a un sistema diferente. Esto crea más copias de datos sensibles, más políticas de seguridad que mantener, más trabajo de integración y más posibilidades de que las respuestas no coincidan.
>
> Oracle Database es una buena opción porque admite los patrones de acceso que necesitan los equipos financieros y mantiene conectada la información. Puede utilizar documentos, vectores, grafos, datos espaciales y aprendizaje automático sin convertir cada capacidad nueva en otro silo.

</details>
